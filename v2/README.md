# AI-EPS 수업 앱 v2 (첫 번째 판)

A의 앱 구조(교사용·학생용 분리, 수업 코드로 입장, 모둠 문서 실시간 공유, 교사 통제)를 뼈대로 다시 만들고,
수업 흐름은 견본 `high/index.html`(고등 지도안 4장 v25 맞춤본)을 그대로 구현했다.

## 여는 법

| 화면 | 파일 | 하는 일 |
|---|---|---|
| 첫 화면 | `index.html` | 교사용·학생용 고르기 |
| 교사용 | `teacher.html` | 로그인(시연용) → 수업 만들기(코드·QR) → 진행 현황 / 도움 자료 / 수업 설정, 인물·자료 점검 |
| 학생용(모둠 화면) | `student.html` | 수업 코드·모둠·이름·비밀번호 4자리로 입장 → 1~7단계 |

ES 모듈과 `fetch`를 쓰므로 파일을 바로 열지 말고 웹 서버로 연다(GitHub Pages 또는 `python3 -m http.server`).

**지금은 시연판이다.** 서버 없이 브라우저 localStorage에 저장한다. 교사 화면과 학생 화면을 **같은 브라우저의 다른 탭**으로 열면
실시간으로 이어진다(탭마다 다른 학생으로 들어갈 수 있다). AI 응답은 견본의 미리 넣은 예시를 흘려보내는(스트리밍) 방식이다.

## 짜임

```
v2/
  index.html  teacher.html  student.html  manifest-student.webmanifest
  css/app.css            견본의 화면 부품 스타일 + v2 껍데기(머리 띠·카드·탭·'지금 할 일')
  js/core.js             저장소, AI 호출, 대기 표시, Red 탐지, 단계 완료 판정, 문서 변경 함수(교사·학생 공용)
  js/student.js          학생 1~7단계 (견본의 s1~s7을 모둠 문서 기반으로 옮김)
  js/teacher.js          교사 화면
  data/high-refugee.json 수업 콘텐츠(편지·기사·문항·사례·예시·시연 응답·지시문·탐지 규칙)
```

- **콘텐츠는 코드와 분리했다.** `data/high-refugee.json`은 견본 코드를 실행해 상수를 그대로 뽑은 것이다(원문 그대로).
  중학교(전자 쓰레기) 판은 같은 짜임의 JSON을 하나 더 만들면 된다.
- **데이터 모델(Firestore로 옮길 때 그대로 쓴다)**
  - `session`: 코드, 제목, 상태(진행 중/닫힘), 리허설 모드, 열린 단계(`open`), 모둠별 AI 열림(`ai[g][n]`), 보완 요청(`req[g][n]`),
    도움 자료 공개(`rev[k] = {all, g:{모둠:값}, t}`), 학생에게 한마디(`broadcasts`), 평가 성취수준(`evalSel`)
  - `groups/{g}`: `members`(이름, 비밀번호 해시, 역할, 마지막 접속, 보고 있는 단계), `work.s1~s7`, `logs`, `alerts`
- **저장 방식(A의 앱과 같은 원리):** 화면 값을 먼저 바꾸고, 입력이 멈춘 뒤 0.6초에 단계(`s1`~`s7`) 단위로 저장한다.
  다른 기기에서 온 변경은 내 쪽에 저장 안 된 입력이 없는 단계만 받아온다. 저장 전에 창을 닫으면 경고한다.

## 모형 원칙이 코드에 들어간 곳

| 원칙 | 구현 |
|---|---|
| 선제 사고 후 AI | 1·3·4·5단계 산출물을 봉인(시각 기록)해야 교사 화면에 'AI 열기'가 나타나고, 교사가 열어야 AI 버튼이 잠금에서 풀린다. 교사는 '보완 요청'으로 되돌릴 수 있다 |
| GYR | 1·3·4·5 Yellow, 2·6·7 AI 미사용. 단계 머리에 AI 역할·도구 이름 표시 |
| Red 탐지 | 학생 입력과 AI 응답의 글자 3-gram 일치율 35% 주의, 60% Red 의심 → 교사 알림(구두 확인 인정/불인정). 붙여넣기도 알림 |
| 교사 단계 개방 | 교사가 연 단계까지만 학생이 들어간다 |
| 도움 자료 | 기본 숨김, 전체 또는 특정 모둠에 공개, 공개 뒤 만든 항목에 '공개 후' 표시. 유사 사례는 1번 전체, 2~5번 요청 모둠에 차례로 |
| 검증 가능한 사실 | 기사·사례마다 출처와 원문 대조 날짜(`checked`)를 데이터에 둔다. 대조 전 자료는 학생에게 보이지 않는다(리허설 모드 제외) |
| 용어 | '예상하지 못한 문제', 3단계 수용·보류·불수용, 4단계 수용·수정·기각 |

## A의 앱에서 가져온 구조·기능

교사/학생 앱 분리, 수업 코드·QR·크게 띄우기·코드 복사·기록 CSV, 수업 닫기, 진행 현황 지표 타일, 학생에게 한마디(전체/모둠),
'지금 할 일' 줄, 연결 상태 표시, 학생 입장(코드·모둠·이름·비밀번호), 모둠원 접속 표시, 기다리는 동안 경과 시간에 따라 바뀌는 안내,
자동 저장과 창 닫기 경고, 원문 확인 전 자료 숨김과 리허설 모드, 인물·자료 점검 화면.
A의 앱에 담긴 콘텐츠(인물, 사례, 문구)는 가져오지 않았다. 반입 판정은 저장소 루트 `CLAUDE.md` 5절에 있다.

## 다음 단계(Firebase)

1. `core.js`의 `store`를 Firestore 구현으로 바꾼다(`get`/`update`/`subscribe` 같은 이름 유지, `update`는 트랜잭션).
2. 교사 Google 로그인(허용 계정 목록), 학생 익명 인증 + 입장 함수(`joinSession`: 코드·모둠·이름·비밀번호 확인).
3. Cloud Functions로 AI 호출 중계: `data/*.json`의 `prompts`를 서버에서 채워 Claude를 부르고, 응답과 호출 기록을 Firestore에 남긴다.
   페르소나 응답은 스트리밍으로 보낸다(A의 앱에서 알려진 '채팅이 느리다' 문제).
4. 시범 전 교사 1명 + 학생 기기 3~4대로 교실 와이파이 점검.
